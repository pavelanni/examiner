# Вернуть доступ отключённому администратору

Исправление по запросу U-004. Старая кнопка «Переключить» меняла активность
пользователя. Её нажатие в строке admin могло отключить самого администратора.
При следующем входе приложение показывало «Неверное имя пользователя или пароль»,
даже если пароль был правильным. Выход из системы пароль не менял.

Теперь свою учётную запись отключить нельзя ни кнопкой, ни прямым запросом.
Для других пользователей кнопки явно называются «Включить» и «Отключить».

## Восстановление на Windows в VS Code

Команды выполняются в PowerShell из папки examiner на вашем ПК. Они относятся
к стандартной базе examiner.db. Если при запуске использовался другой --db,
используйте именно тот файл и соответствующие пути резервного копирования.

### 1. Остановить приложение

В терминале работающего сервера нажать Ctrl+C и дождаться приглашения PowerShell.
Закрытие вкладки браузера сервер не останавливает.

### 2. Получить ветку с исправлением

```powershell
git status --short
```

Если команда показывает незавершённые изменения исходников, сначала сохраните их
или сообщите помощнику: не сбрасывайте их ради переключения ветки.
При чистом рабочем дереве:

```powershell
git fetch origin
git switch fix/admin-self-deactivation-u004
```

При первом переключении Git обычно создаёт локальную ветку из одноимённой
удалённой. Если она уже существовала, обновить её через git pull --ff-only.
Это ветка исправления; до слияния PR обычный git pull в main не добавит новую
команду восстановления. База данных и переменные окружения не являются ветками Git.

### 3. Сохранить копию базы

Сервер должен оставаться остановленным. Каталог резервной копии создаётся
в вашей пользовательской папке вне репозитория:

```powershell
$backupDir = Join-Path "$HOME\ExaminerBackups" ([guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $backupDir -Force
Copy-Item -Path .\examiner.db* -Destination $backupDir
$backupDir
```

Проверьте, что копирование завершилось без ошибки. Шаблон examiner.db* захватывает
основную базу и файлы examiner.db-wal / examiner.db-shm, если они остались после
остановки SQLite. Не удаляйте их и не подменяйте рабочую базу копией.
Резервная копия содержит данные приложения и должна храниться у вас.

### 4. Собрать и выполнить восстановление

```powershell
$env:Path += ";$(go env GOPATH)\bin"
task build BINARY=bin/examiner.exe
.\bin\examiner.exe reactivate-admin --db .\examiner.db --username admin
```

Ожидается сообщение:

```text
Administrator "admin" is active. Password unchanged.
```

Команда включает существующую учётную запись администратора. Она не сбрасывает
пароль, не создаёт нового пользователя и не повышает студента до администратора.
Путь берётся непосредственно из --db; настройки конфигурационного файла
и EXAMINER_DB для этой команды не используются. Если файл не существует,
пуст или не является обычным файлом, команда откажется работать до открытия
SQLite и не создаст базу по ошибочному адресу.
Повторное выполнение для уже активного admin допустимо.

Восстановление выполняется локальным владельцем файла базы; публичной
веб-страницы обхода входа не добавлено. Для команды не требуется запущенная LLM.

### 5. Запустить программу и войти

Использовать прежние настройки модели. В том же терминале:

```powershell
task run BINARY=bin/examiner.exe -- --addr 127.0.0.1:8080 --db .\examiner.db --lang ru --questions questions/physics_ru.json --num-questions 2 --secure-cookies=false
```

В браузере своего ПК открыть http://localhost:8080 и войти как admin
с прежним паролем. Проверить, что пользователи и результаты остались на месте.
На странице управления пользователями в своей строке теперь будет пояснение,
что свою учётную запись отключить нельзя. Выйти и войти ещё раз.

Если отказ входа сохраняется, остановиться на этом результате и сообщить его
помощнику. Пароль не отправлять. Данная команда восстанавливает активность,
но не исправляет забытый пароль или работу с другой базой.

## Как проверено исправление

- Регрессионный HTTP-тест воспроизводил отключение до изменения, а после него
  проверяет запрет запроса, отсутствие своей кнопки, управление другим
  пользователем и повторные входы для путей / и /ru.
- Тесты CLI проверяют повторное восстановление, сохранение пароля и вопросов,
  отказ для отсутствующего пользователя или студента, отсутствие создания
  новой базы по неверному адресу.
- Полный сценарий восстановления дополнительно проверяется на временной базе
  собранным приложением. Настоящие данные пользователя не используются.
- Сборка Windows проверяется отдельно от фактического выполнения на Windows.
  Успех проверки в облачной среде не означает, что доступ на вашем ПК уже восстановлен.
